A little timeline

A prototype became a project we could keep building.

Six small milestones moved Framewise from a visual-builder prototype to a working local app with one home for the code.

01Oct 12

The first Lovable prototype

Create, History, and Help set the direction: plain language up front, FFmpeg detail when it helps.

02Oct 12–13

Choose one home for the code

The Lovable export stayed separate. The private framewise repository became the master project.

03Oct 13

Write down what was missing

A project-status report and next steps made it easier to continue the app outside its original builder.

04Oct 13–14

Keep V1’s “AI” small and local

Keyword matching was enough for a first guide — no model API, account, or secret key needed.

05Oct 14–15

Make commands and setup clearer

Folder-aware desktop paths, friendlier guidance when the helper can't match a request, and official FFmpeg references improved the handoff.

06Oct 15

Run the first-use walkthrough

A manual walkthrough covered resize, a two-file batch, folder input and output, Help, and History repeat.

Things V1 taught us

A little guidance can make a technical tool feel human.

↗

Start with the result

People can explain what they want without knowing FFmpeg flags. Keep goals in everyday language.

⌄

Reveal details at the right time

Optional steps lower the barrier, but repeated copy can still slow the flow. V2 can say less, sooner.

>_

Show what will happen

A readable summary plus a full, copyable command helps the user trust the result and stay in control.

▧

Batch needs a clear status

Show the file count, shared settings, destination, and each file’s progress—not just a multi-select.

✦Evidence note: the first-use walkthrough was a manual check — not a full browser, codec, file-size, or compatibility matrix. There were no formal usability sessions or analytics.

Where V2 could go

Less reading.
Same confidence.

These are design hypotheses to explore, not research findings.

Lead with a few outcome tiles

“Make smaller,” “Change format,” and “Edit a clip” can help a first-time user find the right path faster.

Keep explanations close to the choice

Use a short sentence in the flow and reveal “Why this?” details when someone wants them.

Make batch mode unmistakable

Keep the shared settings, file count, and destination visible as the queue moves.

Explain the first engine download

Set expectations before the first run, then show progress and a useful recovery step.

A useful next session: ask first-time users to compress a clip, make a vertical version, and process a folder — then watch for task choice, command confidence, saved output, and repeatability.

Want to try it locally?

A laptop, Bun, and the project folder are enough.

From the Framewise repository root, install the app packages and start the local development server:

bun install --frozen-lockfile
bun run dev

Browser processing: Framewise uses FFmpeg WebAssembly. You do not need to install native FFmpeg to try conversions in the app.

Copied desktop commands: install FFmpeg on your computer if you want to run a generated command in Terminal or a shell.
