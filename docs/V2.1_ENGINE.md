# Framewise V2.1 Mac engine

## Chosen direction

- Keep the React workflow and the cross-platform Web V1 browser engine.
- Run native FFmpeg from the Tauri Rust backend in the Mac app.
- Pin the bundled Apple Silicon engine to FFmpeg 9.0.2 for this build profile. Upgrade only after Framewise's command and media checks pass.
- Offer a compatible FFmpeg already installed on the Mac as an explicit alternative. Keep the bundled engine as the default and fallback.
- Put engine selection, version/capability details, and maintenance actions in Settings.

## Bundled engine profile

The build script downloads the official FFmpeg 9.0.2 source tarball and verifies its PGP signature against the pinned FFmpeg release-key fingerprint before compiling. It enables Apple's VideoToolbox and AudioToolbox and does not enable FFmpeg's GPL or nonfree options.

This initial LGPL-oriented profile does not include `libx264`, `libvpx`, `libmp3lame`, `libopus`, `libvorbis`, or `libass`. Framewise must inspect the selected engine's encoder and filter capabilities and adapt available choices accordingly. In particular, VideoToolbox H.264 does not use x264's CRF/preset controls; its quality behavior needs its own tested mapping. The system-engine option can expose additional features when that installed build includes them.

The source license for Framewise does not replace FFmpeg's terms. Each distributed engine build needs its matching source, configure command, checksum, and third-party notices. Re-evaluate these materials whenever the version or build profile changes.

## Native execution boundary

The UI sends an argument vector to a Rust command. Rust runs the selected executable directly, with no shell parsing. The native runner owns process output, progress, cancellation, and exit status. The Web V1 path continues to use the browser-only WebAssembly engine.

## Implementation status — 2026-10-22

- Added Rust commands to discover/probe bundled and system FFmpeg, enumerate media inside selected folders, resolve the default Downloads folder, run a native job, stream progress/log events, and stop the running process.
- Added a Mac Settings screen to select the bundled engine, choose a compatible system executable, review its version and capabilities, and refresh the local engine check.
- Added native Mac file/folder/subtitle pickers, dropped-file/folder intake, output-folder selection, batch execution, progress, and cancellation while preserving the Web V1 WebAssembly workflow.
- Native H.264 output prefers VideoToolbox and uses an approximate bitrate target instead of x264 CRF/preset arguments. The app blocks unsupported MP3, VP9, Opus, Vorbis, subtitle-filter, and filter combinations with a Settings link.
- Added a source-build script which downloads FFmpeg 9.0.2, checks the published PGP key fingerprint and detached signature, builds arm64 sidecars, checks the architecture/version/configuration, and records local sidecar hashes. It requires macOS Command Line Tools and GnuPG.
- GnuPG was installed on the Apple Silicon development Mac. FFmpeg's detached source signature verified against the pinned fingerprint `FCF986EA15E6E293A5644F10B4322F04D67658D8`. The corrected clean-source build then compiled FFmpeg 9.0.2 and FFprobe 9.0.2 arm64 sidecars and passed the version, architecture, VideoToolbox H.264, native AAC, crop/scale/GIF palette, and no-GPL/nonfree profile checks. The local sidecar marker records the resulting hashes.
- The Mac frontend production build and Tauri Rust release build completed. Tauri assembled `src-tauri/target/release/bundle/macos/Framewise.app` and `src-tauri/target/release/bundle/dmg/Framewise_2.1.0_aarch64.dmg`. `codesign --verify --deep --strict` passed for the app, `hdiutil verify` passed for the DMG, and the app, FFmpeg, and FFprobe executables are arm64. The DMG SHA-256 is `616244c7eb1e06f71ca0ee19e964bbe0e73bfa51568acbed693b7dd7be68cad4`.
- Tauri applied ad-hoc signing and skipped notarization because Developer ID credentials are not configured. The first restricted packaging attempt could not create the DMG (`hdiutil: create failed - Device not configured`); rerunning the local build with disk-image access succeeded.
- No native app launch, media conversion, batch/cancel workflow, or clean-Mac installation was exercised in this pass. The earlier frontend production build, strict TypeScript check, and Rust `cargo check` remain as previously recorded; the full lint command still reports repository-wide Prettier violations.
- The changed TypeScript sources pass ESLint rules other than the repository's Prettier rule, with one React Fast Refresh warning. The full lint command reports Prettier formatting violations across the source tree, so it is not currently a clean release check.
- The Settings refresh button re-detects engines already on the Mac. It does not download or replace an engine. A signed/checksummed Framewise engine feed and hosted asset must exist before secure in-app engine updates can be implemented.

## Not yet release evidence

This implementation is not proof that V2.1 is ready to distribute. Before a public release, inspect linked system libraries, audit and include the FFmpeg notices/source package, convert representative media for every enabled workflow, verify batch and cancel behavior, verify offline first use, and try the package on a clean Mac. Developer ID signing and notarization are needed for a smoother download-and-open experience.
